## Why PWA here

- **Android Chrome** — full native install prompt, no Play Store needed
- Flaky hospital WiFi → cached shell + branded offline page instead of white screen
- Reception tablet kiosk mode — standalone, no browser bars
- Phase P3 push notifications require an installed PWA base ( groundwork done)

## Architecture decisions

| Decision | Rationale |
|---|---|
| **Static `public/sw.js`** (hand-rolled) | `next-pwa`/`serwist` need `next build` → impossible in this sandbox (OOM). Static SW works in dev AND prod, zero build dependency |
| **`?dev=1` registration flag** | Dev `/next/static` URLs are unhashed & change per HMR compile — cache-first would serve stale CSS. In dev the SW bypasses `/next/*` entirely; prod URLs are content-hashed → cache-first |
| **RULE #1 preserved** | `/api/**`, `/uploads/**`, `/_next/image` are **never intercepted/cached** — patient data can never persist in CacheStorage after logout. SSE/copilot = POST → auto-excluded |
| **Auth-aware HTML caching** | HTML navigations are network-first, **never cached** (login state / PII) |
| **Update flow** | New SW waits (no auto-skipWaiting) → in-app "Update available — Refresh" toast → SKIP_WAITING → controllerchange → 1 reload/session |
| **Self-healing precache** | activate() re-precaches core assets if evicted (cache.add with try/catch) |

## Android user install steps

1. Open the app URL in Chrome (Android) via **Preview Panel → Open in New Tab**
2. "Install App" pill appears (bottom-left) → tap → system install sheet → Install
3. Doctorooms icon on home screen; launches standalone (no browser bars) with teal splash
4. Long-press icon → app shortcuts (Book Appointment / My Dashboard / New Appointment)
